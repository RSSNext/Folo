## Validation

Installed cssnano 9.0.5 and lightningcss 1.33.0 were exercised in Chromium using 14 fixture cases, both separately and together. Across 966 computed-property comparisons, all layout, typography, specificity, fallback, and pseudo-content results matched. Gradient direction/stop normalization, SVG serialization, and relative-alpha color representation produced different strings; screenshots of the complete 312 × 1052 fixture frames showed at most 1/255 difference in any color channel. This explicitly allows the existing color quantization rather than claiming byte-identical CSS or pixels. Fixtures, original/minified CSS, computed results, and screenshots are in `/tmp/folo-css-e2e-20260922/`.

PWA generator 2.0.0 was invoked through the renderer's actual installed binary with a temporary copy of the real TS configuration and the script's `public/icon.svg` argument. It generated 64/192/512 transparent icons, the 512 maskable icon, 180 Apple icon, and 48 favicon. Dimensions and transparent/orange corners passed, HTML links and manifest entries were retained. Five images were pixel-identical to the 1.0.2 baseline after alpha compositing. The maskable image changed 1,001 pixels (0.38%), all on the one-pixel antialiased foreground boundary; foreground bounds stayed `(114, 130)–(405, 407)`, and visual inspection retained the same logo and orange background. This is a renderer/sharp edge difference, not a geometry change. Evidence is in `/tmp/folo-pwa-e2e-20260922/`; no project assets were overwritten.

Landing's production CSS build exposed three invalid `file:disabled:*` selectors. Changing them to `disabled:file:*` restores valid disabled-input file-button styling, and the rebuilt CSS no longer emits those warnings. Landing typecheck and tests passed; its final build/browser results are recorded in the landing review. Frontend agent owns the desktop/SSR production builds. Local rendering validation used Node 26.9.0; the earlier compatibility audit used Node 24.15.0.
