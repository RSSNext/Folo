## Compatibility and migration

[Official Reanimated compatibility](https://docs.swmansion.com/react-native-reanimated/docs/guides/compatibility/) and both packages' published `compatibility.json` list React Native 0.86 for Reanimated 4.7 and Worklets 0.13. Reanimated 4.7 requires Worklets 0.13, so update them together. Expo 57 / RN 0.86.3 stays unchanged. Gesture Handler's 3.3 source still carries the 3.2 compatibility row (RN 0.83–0.87); this is stale version-label metadata, not an explicit 3.3 compatibility guarantee. Its native build source preserves AGP <=8 Kotlin fallback while supporting AGP9, and there is no observed RN0.86 removal. Native build/testing remains required to validate this inference. Existing Expo install exclusions already include all three.

Clear Metro's transformed-worklet cache and rebuild both native apps. A JS-only reload or an old Expo Go binary cannot validate the new native ABI. No app source change was required by the reviewed public APIs.

## Gesture Handler impact

Read `ReanimatedSwipeable.tsx`, legacy detector mount/event handling, Android `GestureHandlerOrchestrator.kt`, `RNGestureHandlerModule.kt`, iOS gesture/button component handling, and Gradle changes. Swipe callbacks now use stable wrappers and `scheduleOnRN`; pan/tap configurations remain stable across callback updates. Disabled or recycled buttons cancel correctly; scrolling cancels presses, keyboard dismissal avoids accidental presses, nested parent/child arbitration and detached-view final events are fixed. Worklets runtime binding now uses the Worklets module directly. Touchable owns its managed native handler rather than delegating through GestureDetector. Legacy `Gesture.Pan()` remains available; relations cannot mix legacy and new hook-based gestures.

Folo affected surfaces: SwipeableItem list actions, picture lightbox pan/pinch/double-tap, sheets, nested ScrollViews, keyboard-open forms and recycled list buttons. Check that swipes survive rerenders and fire actions once, scrolling never activates a pressed item, disabled buttons never submit, pinch/pan finish cleanly when views unmount, and sheet/content scrolling arbitrate correctly.

## Reanimated impact

Read native/web `useAnimatedRef`, `measure.native.ts`, common types, native mutables and fixed Synchronizable state, feature flags, `ReanimatedCommitHook.cpp`, and `ReanimatedModuleProxy.cpp`. UI-side refs changed from callable values to ShareableHost `.value`; exported `measure(ref)` performs the conversion and returns null for absent views. Public JS `.current` and public measure calls are still supported. Folo uses those public APIs in UserAvatar, EntryPictureItem, EntrySocialItem and NavigationHeader; no UI-side `animatedRef()` calls or renamed internal AnimatedRefOnJS types were found. Existing callers accept nullable dimensions.

The new light-tree layout proxy becomes default. Surface lifecycle registration/cleanup, z-index commits, stale transform restoration, exiting view ordering and layout animation retargeting change. Mutables always use fixed Synchronizable dirty flags; the old opt-out flag is removed. CSS callback delivery and native platform transitions are added, with platform transition flags off by default. Folo does not enable removed flags or shared-element transitions.

Verify avatar/image lightbox opening from correct bounds, offscreen/unmounted refs without crashes, list insertion/deletion/reorder transitions, sticky/navigation headers, player controls, loading animation, background/foreground restoration, and overlay z-order. The sheet-transitions patch only changes the provider wrapper/context and border radius; preserve it and verify open/close scale, drag threshold cancellation, corners and scrolling.

## Worklets impact

Read Babel closure/factory transforms, native and web scheduling, `WorkletRuntime.cpp`, Synchronizable atomic access and compatibility changes. Closure metadata becomes arrays and empty closures are omitted; Babel output/native runtime must match. Serializable handles and worklet context objects are removed. Folo/its sheet patch do not access `__closure`, `__init` or custom Serializable handles. `runOnUI` remains available through Reanimated; batching now serializes arguments separately. Hermes microtasks drain in native code and after individual frame callbacks. Runtime teardown aborts pending jobs under the runtime lock, fixing recreation races. Bundle networking moves to its own module; Folo does not opt into it. Existing sheet package code is transformed from ordinary worklet directives, not pinned precompiled closure metadata.

Verify UI↔RN callbacks, consecutive measure/open operations, Promise/error handling, active animations during background/reload, and no native/JS version mismatch after rebuilding.
