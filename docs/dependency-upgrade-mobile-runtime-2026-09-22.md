Generated bindings, examples, and unrelated monorepo packages were separated from the runtime review. Approval here means the source migration is understood; the native build and device scenarios at the end remain separate validation gates.

## Firebase app/core

Read `RNFBApp.podspec`, `package.json`, Expo plugin source, `firebase_spm.rb`, the JavaScript TurboModule resolver and registry, the native event emitter integration, and the Android/iOS thread-safe handle map implementations. v26 requires New Architecture and resolves `NativeRNFBTurboApp`/`NativeRNFBTurboUtils` through `TurboModuleRegistry`; the registry binds native methods lazily while preserving application routing and iOS null serialization. Event subscriptions use the same native host for registration and removal. The handle registry moves entries under a private lock and leaves SDK cleanup outside the lock. Named-app storage now supports prototype-named keys; destruction runs all callbacks even if one fails.

Native dependency versions advance to Firebase iOS 12.18.0, Android BoM 34.18.0, and Firebase JS 12.17.1. iOS minimum is 15, below Folo's configured 16.4. RN 0.86's New Architecture satisfies the architecture requirement. This does not replace an actual build against its generated C++ bindings.

**Migration:** SPM becomes available by default on compatible RN versions. Upstream explicitly rejects SPM with static frameworks because Firebase products produce duplicate symbols. Folo uses `useFrameworks: "static"`. Its Expo app plugin now sets `ios.disableSPM: true`; the plugin writes `$RNFirebaseDisableSPM = true` after `prepare_react_native_project!`, before targets. There is no separate `Podfile.properties.json` key for this setting. Native prebuild must regenerate the Podfile before installing these pods.

## Firebase Analytics

Read the modular `lib/index.ts` implementation and removed namespaced exports, validation/type changes, Android `NativeRNFBTurboAnalytics`, and iOS `RNFBAnalyticsModule.mm` changes. The exported modular `logEvent` returns `void`, though the native operation still uses a Promise internally. Event validation now enforces an alphabetic first character, 1–40 alphanumeric/underscore characters, and reserved prefixes. Consent updates preserve omitted fields instead of implicitly denying them. Native item conversion rejects unsafe casts; iOS session completion is serialized onto the main queue. SHA-256 conversion inputs now require 64 valid hex characters.

**Affected Folo behavior:** launch, navigation, login, subscription and user identity events. `FirebaseAnalyticsTypes.Module` is removed, so the tracker now accepts a small explicit interface and initialization supplies official `logEvent(analytics, …)`, `setUserId`, and `setUserProperties` closures. This keeps native code out of the shared tracker and supports synchronous `logEvent`. Existing Folo mapped event names use valid snake_case. Existing adapter tests retain the internal-property filtering and input immutability checks. Server acceptance of analytics events is not established by those tests.

## Firebase Messaging

Read modular exports/registration and background processing, iOS AppDelegate registration generation handling, FIRMessaging delegate forwarding, notification-center callbacks, Android broadcast filtering and persistent notification storage. Native modules are now TurboModules and exported types use `RemoteMessage` directly. iOS APNs registration has an independent timeout and superseded attempts reject distinctly; cached registration/settings state updates only after native success. Background processing completes even without a handler or when a handler fails. Foreground messages with `content-available: 0` emit correctly. The notification-open event fires for the default action, and existing delegates retain ownership of completion callbacks, which prevents double completion. Android filters control broadcasts, supports a configurable stored-notification limit including zero, and removes stored IDs by exact comparison.

**Migration:** Folo's hook now invokes the official modular token, registration, refresh, initial-notification and notification-open functions. The existing permission → APNs-ready → FCM-token → backend-save sequence and bounded registration retry behavior remain intact. The SDK explicitly documents that ARM64 simulators may time out on real APNs registration. Simulator notification injection can establish navigation behavior but cannot prove APNs/FCM token issuance or delivery.

## Firebase App Check

Read `lib/index.ts`, removed `namespaced.ts`, provider validation and native configuration/token paths. `initializeAppCheck` now synchronously returns `AppCheck`; native provider configuration continues asynchronously. The default namespace factory and its types are removed. Valid Apple provider names include debug, deviceCheck, appAttest and appAttestWithDeviceCheckFallback; Android accepts debug/playIntegrity. Native iOS now fails closed with `appCheck/provider-not-ready` until the real provider is configured rather than installing a debug provider first. Token auto-refresh is enabled after provider configuration.

**Migration:** initialization constructs `ReactNativeFirebaseAppCheckProvider` directly and caches the single returned instance. Token retrieval reuses that instance. A focused helper retries only `appCheck/provider-not-ready` after 25/50/100/200 ms, then preserves the error. Attestation errors do not trigger this retry. The existing request layer's synthetic fallback behavior was not broadened. Auto-refresh is now explicitly supplied in the initialization options, where the SDK consumes it.

## Expo IAP

The package-local changelog is a pointer to centralized release history. Read the official individual release notes across 4.x/5.x, including the 5.0 legacy API removal, and the wrapper source diff: `src/index.ts`, `useIAP.ts`, iOS wrappers, purchase-list decoders, native restore helper, Swift module/helper, and Android Gradle changes.

v5 removes `validateReceipt`, legacy platform request aliases, `inapp`, legacy alternative billing APIs and purchase platform aliases. Canonical requests use `apple`/`google`, and current purchase records identify `store`. The hook now deduplicates purchase delivery from both the native event and request return for 30 seconds. Listener initialization and native Swift cleanup are generation-scoped, so old teardown does not close a new connection. Native query serialization is atomic: malformed entries fail the query rather than disappearing from the returned purchases. Restore propagates native sync failures instead of masking them as an empty successful query. Native error metadata is carried in an envelope, and the JS layer preserves canonical error codes even when Expo adds a source location. Gradle accommodates AGP 9's built-in Kotlin and raises default compile/target SDK fallback to 36; Apple/Google native dependencies are 3.4.0/3.5.2.

**Migration:** `AppleIAPProvider` now destructures `verifyPurchase` as `verifyStorePurchase` for the optional JWS retrieval fallback. `getTransactionJwsIOS`, canonical `request.apple`, `type: "subs"`, and the explicit no-auto-finish option remain supported. The authoritative flow still sends the signed transaction or transaction identity to Folo's backend, waits for successful verification, then finishes the transaction. Local store verification alone never grants entitlement. Current app code does not consume the removed platform aliases. The app's own transaction dedupe remains useful across native redelivery and failed backend verification.

The existing localhost `StoreKitTestHelper.buyProduct` shortcut bypasses the `expo-iap` purchase request/hook path. Passing that shortcut alone is insufficient evidence for this upgrade. Native E2E should exercise the actual `useIAP` product request, purchase callback, verification and finish path, plus user cancellation and restore failure/success.

## PostHog React Native

The npm metadata has no `gitHead`. The upstream feature commit used in the comparison still contains a 4.74.2 package/changelog version, so the official 4.75.0 release body was separately read: it identifies commit `5cfec8b` and adds partial survey responses with persistent resume. This provenance distinction is deliberate.

Read the intervening changelog and implementation changes in `src/posthog-rn.ts`, error tracking context/handlers, optional Expo Updates/native plugin loading and lifecycle paths. Changes relevant to Folo include safer identity/reset persistence, native identity/consent serialization, error-handler sharing across clients, restoring the previous RN error handler on shutdown, and a two-second cap on persisting fatal exceptions before handing control back to RN. Exceptions can include release-time Expo update metadata and current app state. A failing before-send hook drops an event; it no longer sends the unmodified event. Feature-flag reload fixes prevent stale identity evaluations. Shared-core notes also describe bounded retries, offline flush coalescing, preserving newly queued events during an in-flight flush, and the Hermes random-number/UUID edge-case fix.

New push subscription and opened-event capture default to enabled **only with the optional native plugin**; those native events bypass JS `before_send`. Folo currently installs neither that plugin nor the legacy replay plugin, so that new bridge path is unavailable. No optional native plugin was added by this migration. Folo still constructs the JS client with its session-level 5% `before_send` sampler and uncaught/unhandled error capture. Surveys, native replay, symbol-upload tooling and new push APIs are not directly consumed by the current initialization. If adding the optional native plugin later, its push defaults must be reviewed against the intended sampling/notification policy.
