# Landing dependency review — 2026-09-22

## vinext 1.0.0-beta.0 → 1.0.0-beta.11

Read all eleven intervening [official releases](https://github.com/cloudflare/vinext/releases) and the application-consumed changes in the [upstream diff](https://github.com/cloudflare/vinext/compare/4fad98a20e226e2031faaa6a6b7fa4cdd0065510...468f72eaba537718217b63c5b495cf5d181da4e0). Local evidence: `/tmp/folo-dependency-review-20260922/vinext/` (`review-releases.md`, complete `source.diff`, and focused source extracts). This is a scoped review of the App Router and Worker paths used by landing, not a claim that every upstream Pages Router or generated declaration change was read.

- **Configuration and build identity:** explicit Vite aliases now precede inferred tsconfig/shim entries and are copied without mutating the object retained for server restart. This directly affects landing's `next-intl/config` alias. React is deduplicated in all environments. New compiler opt-in and multi-stage Worker/CDN options are not enabled by this update. Import-meta transforms distinguish project sources from bundled dependencies and use emitted identities, avoiding build-host paths and unnecessary Worker `process.cwd()` access. Vite worker bundles receive their own image-import plugin.
- **Routing and middleware:** read `middleware-matcher-pattern`, `middleware-runtime`, `app-rsc-handler`, and request/redirect normalization changes. Matcher configuration is validated; patterns that can cause excessive backtracking are rejected. Landing's ordinary `/:path*` remains supported. Matching tries encoded then once-decoded paths; userland middleware receives the original encoded path with `.rsc` and transport `_rsc` normalization kept separate. Internal locale rewrites retain query values. Middleware-eligible single-stage requests now remain private rather than allowing a CDN hit to bypass middleware. Interception-selector validation and source authorization are stricter; landing does not use intercepted/parallel routes.
- **Request state:** `headers` and cookie shims keep speculative dynamic-usage probes in child async scopes and propagate dynamic classification without contaminating siblings. Middleware cookie overlays remain visible to `cookies()` separately from raw request `headers()`. Cookie mutations synchronize at action→render phase; SameSite/partitioned/priority metadata is normalized and emitted. Landing's download page reads request headers; no application server actions or direct cookie mutation were found.
- **SSR and metadata:** read `app-ssr-entry`, `app-ssr-stream`, `app-page-stream`, metadata resolver/rendering, and metadata-route response changes. Dynamic SSR yields one React task before the first HTML pull; completion and metadata readiness are tracked separately. Flight byte chunks are preserved without broad string replacement and can be mirrored into the Next transport. `generateMetadata`/`generateViewport` receive parent metadata; viewport-fit and theme-color normalization are supported. Streamed icons carry stable ownership/order markers. Metadata endpoints honor cacheability, avoid caching explicit no-store, and support generated sitemap identities. These paths affect every localized layout, title/description/OG tags, favicon, viewport, and robots output.
- **Fonts:** Google/local font state is shared across module instances using global symbols, local font identifiers derive from the actual declaration, and preload URLs match hashed font sources. Landing uses Geist through `next/font/google`; check CSS, preload delivery, and no hydration differences.
- **Browser navigation:** read navigation runtime/shim and bootstrap/history/hydration changes. Raw query spelling is preserved independently of URLSearchParams serialization; static HTML may hydrate search parameters from the browser. Prefetch freshness is checked on lookup, server/config stale bounds are combined, a navigation promotes its queued prefetch, superseded setup is cancelled, and history snapshots preserve the appropriate tree. Fragment scrolling defers to the next frame. Initial hydration seeds visited history rather than preventing a subsequent Link prefetch. Test localized links, query/hash, back/forward, and quick navigation after hydration.
- **Worker entry:** read `app-router-entry` and image optimization diff. Instrumentation and cache/image adapters initialize before user rendering; trusted prerender state comes from platform context and external internal headers are filtered. Asset subrequests preserve original request semantics. The only image-size default change removes width 16. Landing's custom Worker previously forwarded only `request`; it now forwards `env` and `ctx` to retain ASSETS access and waitUntil/revalidation lifecycle. No deployment occurred.

## Validation

Installed vinext beta.11 with Vite 8.3.0, Cloudflare Vite plugin 1.57.1, RSC plugin 0.5.35, and next-intl 4.14.6. `pnpm --filter @follow/landing build`, `typecheck`, and `test` passed; the test run contains 9 passing tests across 4 files. Targeted ESLint of every changed landing source and test also passed. The production build generated the Worker and standalone outputs. Existing partial-webpack-support and large-chunk/plugin-time warnings remain; the invalid file-input pseudo-selector warnings were fixed as described in the CSS review.

The emitted Worker ran through the Cloudflare Vite preview at `127.0.0.1:4399`, rather than a development server. Actual HTTP checks covered all three locale home pages (200), English/Chinese pricing (200), Japanese/English download (200), privacy policy (200), robots (200/plain text), both AASA paths (200/JSON/cache 300), an unknown route (404), and the custom image endpoint. Width 128 returned JPEG with immutable caching; removed width 16 correctly returned 400. Final results are in `/tmp/folo-landing-http-final.json`; server/build/check logs use `/tmp/folo-landing-*.log`.

Browser checks used agent-browser with installed system Chrome, not Playwright's bundled browser. Verified:

- Hydrated Human/Agent tabs switch both ways and render the agent skill link; fallback feed cards render the expected titles. Geist fonts load and the page has the expected title, description, canonical, viewport-fit, and light/dark theme metadata.
- Header navigation reaches pricing/download; monthly and annual billing display their respective prices. Back/forward restore the previous page and the exact `dep=a%20b+z` query spelling. The Built Open fragment link reaches `/#open` and brings the section into view.
- Chinese links retain `/zh`, Japanese download content and `html` language render, and macOS request headers choose the macOS download group. Expanding other downloads exposes iOS, Android, Windows, and Linux with the expected destinations. No installers or external account actions were triggered.
- The 375 × 812 Chinese download layout and 1440 × 1000 desktop layout were visually inspected. Browser page-error collection was empty after these interactions. Screenshots include `/tmp/folo-landing-zh-mobile.png`, `/tmp/folo-landing-downloads.png`, and `/tmp/folo-landing-home-final.png`.

The production-like run exposed an existing unbounded upstream wait in landing's own data fetches. The homepage stalled when public API requests did not respond, and the discover-sources route had the same issue. Both now abort requests after 5 seconds and use their existing fallback data. New behavior tests cover stalled hero/metrics requests, successful response timer cleanup, discover fallback/retry/cache headers, and successful discover caching. On the rebuilt Worker the locale home pages returned in 7–9 seconds including rendering, and discover returned 24 fallback entries in 6 seconds with `max-age=60`. These are observed end-to-end durations, not a claim that a 5-second fetch deadline bounds total rendering to exactly 5 seconds. Successful public production API freshness was not verified; the local checks exercised the fallback path.

No Cloudflare deployment was performed. The existing `cf:deploy` scripts invoke `vinext deploy`, which already reported removal in the old beta.0 CLI as well as beta.11; repository workflow search found no callers. This pre-existing publishing-script limitation was recorded rather than introducing an unaudited deployment package. Local production Worker build and execution passed, but they are not evidence of a deployment.
