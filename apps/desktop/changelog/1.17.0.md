# What's new in v1.17.0

## Shiny new things

- New "Autoplay videos" setting in General: turn it off and YouTube and Bilibili embeds, hover previews and media previews wait for a click before playing

## Improvements

- Changes made offline or while the server is unreachable are kept and sent as soon as the connection is back; only changes the server refuses are undone, and the app tells you why
- Offline, a feed without stored entries says it is offline instead of loading forever, and loads once you are back online
- Find in page keeps every keystroke, no longer counts its own text, steps through matches in order, has its editing menu back and leaves no highlights behind after closing
- Links to footnotes and other sections inside an entry scroll to them
- RSSHub routes that need a paid plan, such as X (Twitter), show an upgrade button in the follow form instead of a fetch error
- The RSSHub page explains that Folo's built-in instance is used first and your own instance is the fallback, and checks an instance address before saving it
- Editing Actions on two devices no longer overwrites the other device's rules: you can load the latest rules, keep editing or save over them
- Clearer, translated errors for a wrong email or password, too many requested emails, refused sign-in links and provider sign-ins, feeds the follow form could not load, and an unreachable server instead of "Failed to fetch"
- Verified accounts are told that an email change is approved from the current address first
- AI replies wait as long as the server does, and a stalled reply ends with the server's error in your language
- Saving media suggests a clean file name
- A Google Play subscription opens Google Play to manage it
- Analytics no longer receives your name, email or handle

## No longer broken

- Fixed a new device or browser replacing the account's AI shortcuts with the built-in ones after signing in
- Fixed the previous account's settings, including AI provider keys and MCP headers, being uploaded to another account that signed in on the same device
- Fixed signing out or switching accounts reopening the last entry, which the next account then marked as read
- Fixed changes queued under an expired session being sent with the next account's session
- Fixed stars and read marks clicked offline doing nothing and getting lost on reload
- Fixed setting changes that failed to send waiting for the next change or launch
- Fixed syncing starting up to a minute late after signing in on a new device
- Fixed unread counts after a refused Mark all as read, a deleted list or a feed removed from a list, and counts staying one below the server's after launch
- Fixed folder renames and subscription edits undoing changes made on other devices
- Fixed saved regex patterns such as (?i)foo blocking every later save of Actions
- Fixed a short timeline keeping a loading skeleton at its end after a refresh
- Fixed the window not refreshing stale data when brought back from the Dock or the tray
- Fixed push notifications stopping after a failed token upload until the next sign-in
- Fixed the follow form saying "Updated" after a first follow instead of "Followed"
- Fixed Discover offering Follow again after a restart for an RSSHub instance address you already follow
- Fixed MCP authorization reporting a blocked popup
- Fixed folo:// links with unknown paths opening hidden windows that never closed
- Fixed the find bar blocking clicks on the entry header buttons below it
- Fixed a subscription in an unknown view emptying the app
- Fixed the spacing of the Chinese "Mark as read" button
